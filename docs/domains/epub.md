# EPUB domain

## Overview

`src/formats/epub` decodes EPUB 2 and EPUB 3 files into the core `Book` model. It consumes the zip reader (`src/zip`) for container access and registers through the public format seam as `epub: BookFormat` (re-exported from `src/formats/index.ts`), so `open(bytes, { formats: [epub] })` is the whole integration. Modules: `index.ts` (sniffer, decoder, zip→core error bridge, `Book` assembly), `opf.ts` (container document + OPF package parsing into plain data), `xml.ts` (the internal XML parser and element helpers). Format knowledge comes from the W3C EPUB 3 / OCF / OPF specifications only.

## Key decisions

- **XML is parsed by a minimal internal parser, not `DOMParser`** (2026-08-24). Node has no `DOMParser`, decoder tests must run headless under `node:test`, and zero runtime dependencies forbids an XML library; running decoder correctness under Playwright would make a browser a test gate, which the tooling stance rejects. So `xml.ts` implements a small well-formed-XML walk sufficient for container.xml and the OPF. It lives entirely inside `src/formats/epub` — no XML surface or environment shim leaks into `src/core`. Its limits are deliberate (see Gotchas) and acceptable because the decoder only parses the two small spec-defined package documents, never book content.
- **The decoder is the zip→core error bridge.** `src/zip` throws zip-local errors and knows nothing about core; every zip call in the decoder goes through a bridge that rethrows `ZipEncryptedEntryError` as `EncryptedContentError` and any other `ZipError` (malformed structures, missing entries, truncation) as `CorruptContainerError`, always with the zip error as `cause`. A raw `ZipError` never escapes `open()`.
- **Sniffing opens the archive rather than trusting byte offsets.** After a cheap `PK\x03\x04` check, the sniffer reads the `mimetype` entry through the zip reader and compares against `application/epub+zip`. This tolerates real-world archives where `mimetype` is not the first entry or is compressed (both OCF violations); any sniff-time failure returns `false`, never throws. Trailing whitespace after the media type (commonly a newline) is tolerated via `trimEnd()`; leading garbage is not.
- **Namespace handling is by local name, not URI resolution.** Elements and attributes match on the name after the prefix (`dc:title` → `title`, `opf:role` → `role`); `xmlns` declarations are ignored. The two package documents use small, distinctive vocabularies where local names do not collide, and this also absorbs publishers who use nonstandard prefixes or a default namespace.
- **Cover detection prefers EPUB 3, falls back to EPUB 2.** A manifest item with `properties` containing `cover-image` wins; otherwise `<meta name="cover" content="...">` in the metadata resolves by manifest id, then by href (some publishers put the image href in `content` instead of the item id). No cover means `metadata.cover` is omitted — never an error.

## Implementation notes

- Decode flow: open zip → read `META-INF/container.xml` → first `<rootfile>` with `media-type="application/oebps-package+xml"` (or the first rootfile at all) gives the OPF path → parse the OPF into an `OpfPackage` → assemble the `Book`. Malformed container or OPF XML is caught and wrapped in `CorruptContainerError` with the parse error as `cause`.
- `OpfPackage` (`opf.ts`) keeps everything later work needs: the OPF path (hrefs resolve relative to its directory), the full manifest (`id`/`href`/`media-type`/`properties`), spine idrefs in order, and `<guide>` references. The `Book` uses a subset; TOC and resource-resolution work read the rest without re-parsing.
- Sections are the spine itemrefs resolved through the manifest, in spine order, with the manifest item id as section id; `linear="no"` itemrefs are included. Idrefs that resolve to no manifest item, and duplicate idrefs, are skipped rather than fatal. Non-spine manifest items become the `resources` map, keyed by manifest id.
- Section/resource `load()` is lazy through the zip reader and currently uses the manifest href verbatim as the zip entry name — correct only while the OPF sits at the container root, which the committed fixtures do. Resolution relative to the OPF directory is the next unit of work in this domain; until it lands, corpus books with an `OEBPS/`-style layout decode (metadata, spine, structure) but their `load()` calls would miss.
- `toc` is `[]` for now (nav document / NCX parsing is not implemented yet); the NCX and nav documents already sit in `resources` untouched.
- Package documents decode as UTF-8, or UTF-16 when a BOM says so — the encodings the EPUB spec allows.
- Fixtures in `test/fixtures/epub/` are generated by `make-epub-fixtures.mjs` in that same directory (invented text, byte-level zip writer that keeps `mimetype` first and stored, real 1×1 PNGs for covers). Corrupt-container and non-EPUB fixtures cover each failure mode; `test/corpus/` books (gitignored) get a decode pass that skips when the corpus is absent.

## Gotchas

- **The internal XML parser is not a conforming XML processor.** It handles elements, attributes (quoted only), text, CDATA, comments, processing instructions, and skips DOCTYPE declarations (including internal subsets) without reading them. It does **not** support: DTD-defined entities (only the five predefined ones plus numeric character references decode; unknown entities stay literal), namespace URI resolution, attribute-value normalization beyond entity decoding, or well-formedness checks it doesn't need (it does reject mismatched/unclosed tags, a missing root, and a second root element). Never point it at book content (XHTML chapters routinely carry DTDs and named entities) — package documents only.
- The spec says `mimetype` must be first and stored; sniffing deliberately does not verify placement or method, only content. Do not "fix" the sniffer to enforce the spec — real books violate it.
- `<meta name="cover">` vs EPUB 3 `<meta property="...">` share a local name; they are distinguished by attributes, not element name. The EPUB 2 cover meta is matched only when `name="cover"` is present.
- Gutenberg EPUB3 builds and Standard Ebooks declare the cover **both** ways (`properties="cover-image"` on the item *and* an EPUB 2 `<meta name="cover">`), so the corpus never reaches the EPUB 2 fallback — only the committed EPUB 2 fixture proves that path. Standard Ebooks' `<meta name="cover" content="cover.jpg">` uses an item id that looks like a filename; resolution is by id first for exactly this reason.
- `exactOptionalPropertyTypes`: `BookMetadata` and `OpfPackage` optional fields are built with conditional spreads — never assign `undefined`.
